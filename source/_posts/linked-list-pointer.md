# 链表里的结点、指针、元素，到底是什么关系

做链表题的时候，最折磨人的不是算法，而是**概念没分清**：`p`、` *p`、`p->data`、`q->next = p`……每个符号都认识，连起来就晕。这篇笔记把它们一次讲透。

## 三个概念，先分家

```c
typedef struct Node {
    int data;            // 数据域：存的"元素"
    struct Node *next;   // 指针域：存的是地址
} Node;

Node *p;                 // p 是一个"指针"：它本身只是一个装地址的变量
```

- **指针（pointer）**：`p` 里装的是一个**地址值**，比如 `0x7ffd1000`。它自己不存数据。
- **结点（node）**：`*p`，是那个地址指向的**一整块内存**——包含 `data` 和 `next` 两个域。
- **元素（element）**：`p->data`，也就是 `(*p).data`，是结点里真正存的**数据**。

一句话：**p 拿着地址，*p 是房子，p->data 是房子里的东西。**

## `q->next = p` 到底干了什么

这是链表题里出现频率最高的语句，记住：**它只是在"抄地址"**。

```
q->next = p     // 把 p 里装的地址，复制一份，放进 q 的 next 域里
```

执行前：

```
q --> [data|next: ??? ]        p --> [data|next: ...]
```

执行后：

```
q --> [data|next: ──────┐
                        ▼
                   p --> [data|next: ...]
```

q 的 `next` 和 p 指向了**同一个结点**。注意：没有复制结点，没有"把 p 接到 q 后面"这种魔法，就只是抄了个地址。

同理，`q->next = q` 就是让 q 的 next 指向**自己**——一个自环，写出来看着诡异，但语义就是"抄自己的地址给自己"。

## 双向链表：`p->prior` 是谁的？

```c
typedef struct DNode {
    int data;
    struct DNode *prior, *next;
} DNode;
```

`p->prior` 是 "**P 这个结点里面的 prior 域**"，它装的是 P 的前驱结点的地址。删除 P 结点时要同时改两条链：

```c
p->prior->next = p->next;   // 前驱的 next 绕过 P，指向 P 的后继
p->next->prior = p->prior;  // 后继的 prior 绕过 P，指向 P 的前驱
```

## 插入的通用方法：画图对比法

考试插入题（比如"在 q 和 p 之间插入 s"）的通用解法，三步走：

1. **画插入前的样子**（q 和 p 原来怎么连的）
2. **画插入后想要的样子**（q → s → p）
3. **对比哪几根"箭头"变了**，按顺序写语句

关键顺序：**先连后继，再断前驱**。先让 s 的 next 指向 p，再改 q 的 next 指向 s。如果顺序反了，q->next 一改，原来 p 的地址就丢了（没别的指针存着的话），链表直接断掉。

```c
s->next = p;      // 先：s 接住 p
q->next = s;      // 后：q 改指向 s
```

## 几个容易混的名字

| 名字 | 是什么 |
|---|---|
| 头指针（head pointer） | 指向第一个结点的**指针变量**，链表的"入口" |
| 头结点（head node） | 第一个结点**之前**的附加结点，data 域不存有效数据 |
| 首元结点 | 真正存第一个有效数据的结点 |
| 尾指针 / 尾结点 | 指向最后一个结点的指针 / 最后一个结点本身 |

头指针是链表**必须有**的（不然找不到链表），头结点是**可选的**（加了之后插入删除不用单独处理第一个结点，代码更统一）。

## 一句话总结

链表题里，永远问自己：**"这个符号里装的是地址，还是地址指向的东西？"** 分清这一层，`->` 和 `*` 就再也不会打架了。
